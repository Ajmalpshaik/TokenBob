# TokenBob Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build TokenBob, a WPF desktop widget that hangs from the top edge of one monitor on a physics rope and shows the Claude 5-hour and weekly limit usage.

**Architecture:** `TokenBob.Core` (net10.0, no UI) holds physics, usage fetching, polling, alerts, placement, settings, gesture recognition and display text, all unit-tested. `TokenBob.App` (net10.0-windows, WPF) is a thin shell: a transparent topmost window, renderers, Win32 interop, settings window and tray icon, verified manually.

**Tech Stack:** C# / .NET 10, WPF, xUnit, Microsoft.Extensions.TimeProvider.Testing, H.NotifyIcon.Wpf, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-14-tokenbob-design.md`

## Global Constraints

- Core targets `net10.0` and must not reference WPF/WinForms. App targets `net10.0-windows`. Tests target `net10.0` and reference Core only.
- `Directory.Build.props`: `Nullable=enable`, `ImplicitUsings=enable`, `TreatWarningsAsErrors=true`, `Version=0.1.0`.
- All Core geometry is in **logical px** (DIPs) unless a name says `Device`. Monitor bounds are device px plus a `Scale` (dpi / 96).
- Rope: 14 points; fixed timestep 1/120 s; rest length 60–400 logical px; anchor ≥ 40 logical px from each monitor edge; default anchor 120 logical px in from the right edge of the primary monitor; default rope length 150.
- `OrnamentAngle`: radians, 0 = hanging straight down, value is `-atan2(dx, dy)` of the last rope segment so it can be fed directly (×180/π) to a WPF `RotateTransform`.
- Pull-to-refresh: stretch ratio > 0.25 at release; 30 s cooldown (shared with every manual refresh).
- Hover delay 400 ms. Wind radius 80 logical px.
- Color levels: Green `< 60`, Amber `60–85` inclusive, Red `> 85`. Shiver `≥ 90` (5-hour only). Notifications at 80 and 95 for both limits, once per limit window.
- Refresh interval choices `{1, 2, 5, 10, 15}` minutes, default 5. HTTP timeout 10 s. HTTP 429 → delay doubles each time, capped at 30 min; success resets to the interval.
- Fullscreen check every 2 s.
- Usage source: the user's claude.ai session in TokenBob's own WebView2 profile `%AppData%\TokenBob\WebView2`. Endpoints `GET /api/organizations` and `GET /api/organizations/{uuid}/usage` on `https://claude.ai`, run as same-origin `fetch` calls in a hidden WebView2. Sign-in URL `https://claude.ai/login`.
- Sign-in window top-level navigation lock: `https` only; hosts `claude.ai`, `anthropic.com` (and their subdomains), `accounts.google.com`. Everything else is cancelled.
- **Never** read Claude Desktop's or Claude Code's stored logins. Never commit, upload, or log cookies, response bodies, or the organization id.
- App data root `%AppData%\TokenBob\`: `settings.json`, `alert-state.json`, `logs\tokenbob-yyyyMMdd.log` (files older than 7 days deleted at startup).
- Usage page URL `https://claude.ai/settings/usage`. Repo URL `https://github.com/Ajmalpshaik/TokenBob`.
- UI copy, verbatim: `Sign in to Claude to see usage` · `Offline — updated {N} min ago` · `Can't read usage right now` · `Loading usage…` · tray tooltip `5h {a}% · Week {b}%`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on `main`; push after each task once the repo exists (CI must stay green).

## Review Focus

1. **Mixed-DPI monitors** — Shift + dragging from a 100% monitor onto a 150% monitor must use the *target* monitor's scale for margins and rope length, not the source's. Test in Task 7.
2. **No active 5-hour window** — the server can return `five_hour: null` or `resets_at: null` when you haven't used Claude recently. Expected: 0% and "Not started yet", never "Can't read usage". Tests in Task 4 and Task 11.
3. **Cloudflare / HTML challenge page** — claude.ai sometimes answers with an HTML "checking your browser" page, even as a 403. That must show "Can't read usage right now" (keep last numbers, retry), never "Sign in", which would send you to sign in for nothing. Test in Task 4.
4. **Sleep / resume** — after the PC wakes, the first frame can be minutes long. The rope must stay finite and near the anchor, and usage must refresh. Test in Task 3; resume refresh in Task 11.
5. **Hand-edited or newer-version settings file** — out-of-range values (rope 5000, interval 7) and unknown fields must clamp/ignore, not reset everything or crash. Test in Task 8.

Spec refinements made by this plan (no behavior change): gesture recognition, wind detection and display text live in Core so they can be tested; settings and alert state share one `JsonStore<T>`; `UsageError` is `NotSignedIn | Offline | RateLimited | Unreadable` (RateLimited shown like Offline); a null limit object/`resets_at` is valid (Review Focus 2).

Starting values (tune until tests pass, then by eye in Task 9): gravity 1800 px/s²; 12 constraint iterations with stiffness 0.92 (lets the rope stretch); ornament point treated as 3× heavier than rope points; linear damping per second `lerp(3.0, 0.6, SwingStrength)`. `Grab` pulls the ornament point toward the target by 35% per step, and while grabbed the ornament point is pinned during the constraint pass (like the anchor), so a hard pull stretches the rope instead of being pulled back. Ornament angle is an angular spring: `accel = 90·(target − angle) − lerp(14, 6, SwingStrength)·angVel`. `IsAtRest` = max point speed < 2 px/s and |angVel| < 0.02 rad/s continuously for 1 s; while at rest, `Advance` is a no-op. `Grab`, `ApplyImpulse`, `Freeze(false)`, and setting `Anchor`/`RestLength` wake it.
